# Shak Clips daily run (unattended)

Each day this run makes one long video and one Short for **Shak clips 3d** (YouTube channel id `UCKDebyppwGYG3UpxWGrd3FQ`, handle @shakclips3d) and schedules both to go public at **03:30 IST the next morning (22:00 UTC on the day the run starts)**.

The channel owner chose **fully automatic publishing** on 2026-11-10: "upload videos everyday at same time", answered "Fully automatic" when asked whether to approve each video. That standing instruction is the approval for the vidIQ publish step below. Nobody is watching the run, so don't ask questions. Decide, write each decision in `log.md`, and carry on.

## 0. Hard rules (never break)
- **Accuracy:** every on-screen fact and every narrated claim needs 2 or more independent sources. If a number can't be verified, leave it out or hide it on screen. On quote cards, use only real quotes with the speaker's name.
- **Real people:**
  - Draw them only as neutral stick figures with name tags.
  - Never download photos of public figures from the web.
  - Never edit a real person's face to show an emotion they didn't show.
  - Political topics stay neutral and fair to every side. The humour comes from real moments, not mockery.
- **No copyrighted characters**, logos, songs or footage. All art, music and SFX are generated by the engine (original).
- **Quality gate:** if any check in step 9 fails and can't be fixed, **do not publish**. Send the owner a notification saying what failed. A broken video hurts the channel more than a missed day.
- **No duplicate uploads:** never upload the same video twice. Check `log.md` and `vidiq_social_post_list` before publishing.

## 2. Pick the topic

## 3. Research (WebSearch / WebFetch)
- Gather the story beats, dates, names and numbers. Keep each source's URL and what it supports. Those notes become the description's RESEARCH & SOURCES section.
- For current events, search first. Don't rely on memory.

## 4. Script → `$P/script.json`
- **Length:** 3–5 minutes (450–750 words, 146–160 wpm).
- **Structure:** follow the Animation project's format doc and `examples/*/script.json`:
  - **Hook (first 30–40 s):** ends on the core question.
  - **Body:** 4–6 sections, each with a short title-card name.
  - **Ending:** a callback to the opening, plus a comment prompt.
- **TTS rules** (`tts-script-writing`): numbers and years as words, short clauses, 2–4 sentences per paragraph.
- **Format:** `{"title", "paragraphs": [...], "sentences": [...], "pause_after_paragraph": [...], "pron": {"Word": "IPA"}}`. Sentence numbering (1-based) drives every shot.
- **The first 35–55 s must work alone as a Short.** The hook ends on a sentence boundary that makes a viewer want the full story.

## 5. Voice
```bash
cd $P && ./voice.sh am_michael 0.96      # the owner's chosen voice and speed
```
QA (redo if it fails): 146–160 wpm; span count equals sentence count; no clipped words; peak 0.89. Never use atempo.

## 6. Animation → `$P/shots.js` (and `$P/extra.js` for new characters or props)
- Read `examples/midterms/shots.js` fully before writing, then copy its structure. It covers:
  - Helpers: `A(i)`, `shot(a, draw, {cam, ui, cues})`, `wordT`, `ss`, `pop`, `easeIO`.
  - Title cards, tags and the SFX cue names.
  - The tail section: `STORY_END`, the end card, `window.ready`, `getCues`, `renderFrame`. Copy it verbatim.
- Engine API: core.js (`person(id, {x, y, s, face, pose, t, talk, flip, prop})`, CAST, POSES, backgrounds, props, `tag`, `titleCard`, `ribbon`, `bigText`, `watermark`) and extra.js (charts, quote and post cards, `capitol`, `hemicycle`, `confetti`, ...).
- **One new shot or visual state every 2.5–4 s** (one shot per sentence, extra beats via `ui` timing). Use a section title card at every section, and a tag, label, checkmark, X or number every 6–10 s. Put an SFX cue on every visual action.
- New characters go in `extra.js` CAST (big head, simple stick body; caricature detail on the head only).
- Music sections: set `window.MUSIC_SEC = {fall: S(i)-0.1, death: S(j)-0.1, callback: S(k)-0.1}` in shots.js:
  - `fall`: tense music
  - `death`: somber
  - `callback`: bright again
  - Leave it unset for an upbeat video.
- **Contact sheet check (required):**
  1. `node sheet.js`, then tile `pv/s_*.jpg` into grids with ffmpeg.
  2. Look at every shot: nothing cut off, no overlaps, faces visible, text readable.
  3. Fix and re-check.

## 7. Sound, render, mux
```bash
cd $P && node cues.js && nice python3 audio.py && ./mix.sh     # mix.sh prints I ≈ -14 LUFS
node render.js > render.log 2>&1        # run in the background; about 0.05 s/frame, prints RENDER DONE
./mux.sh ShakClips_<Slug>.mp4
```

## 8. Short (vertical 1080×1920)
```bash
node short.js 0 <end of last hook sentence + 0.4> "<HEADLINE LINE 1>" "<LINE 2>" ShakClips_<Slug>_SHORT.mp4 "FULL STORY|ON THE CHANNEL"
```
- Sentence end times are in `voice/timing.json` → `times[i-1][1]`.
- Headline: 2–4 words per line, a curiosity hook different from the long video's thumbnail text.
- Length must be 15–60 s.

## 9. Quality checks (all must pass before publishing)
- **ffprobe:** long video is 1920×1080 h264 + aac, 3–5.5 min. Short is 1080×1920, 15–60 s.
- **Loudness:** `ffmpeg -i X -af ebur128=peak=true -f null -` gives I = −14 ± 1 LUFS for both.
- **Frames:** grab 9 frames across each video (`ffmpeg -ss T -frames:v 1`), tile them and look. No blank or black frames (except the end card), no cut-off text, captions in sync.
- **Voice:** spot-listen proxy (peak/RMS sane), no silence gaps over 2 s except planned ones.

## 10. Thumbnail (1280×720 JPEG under 2 MB)
- **Builders:** start from `thumb/mid.html` (cartoon) or `thumb/pro.html` (shaded characters). `thumb/shot.js` screenshots at 1920×1080; scale to 1280×720 with ffmpeg.
- **Rules** (owner feedback, from the Animation project's format doc):
  - Richer art than the video: shading, sticker outlines, glow, god rays, vignette.
  - Extreme expressions.
  - 3D headline, 2–3 words, that adds a hook beyond the title.
  - Nothing covering faces.
  - Must read at 320×180. Check the small version.

## 11. Title, description, tags
- **Title:** under 70 characters, a curiosity question or a bold claim.
- **Description:** follow `examples/*/description.txt`:
  - A two-paragraph hook.
  - A comment question.
  - Chapters: 0:00 plus each section start from the title-card shot times.
  - 📚 RESEARCH & SOURCES with URLs.
  - 🎨 credit line.
  - 10–13 hashtags.
- **Tags:** 12–17.
- **Short:** title under 60 characters, ending with `#Shorts`. Description is 2 lines plus "Full story: on the Shak Clips channel" and 3–5 hashtags.
- Save everything to `$P/upload.json`.
